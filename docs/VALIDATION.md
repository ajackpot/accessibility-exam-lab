## 통과: 실제 브라우저 UI

- 키보드만으로 시작 → 필기 설정(인터넷,2문항) → 시작 → 라디오 방향키 → 빈 답 확정 오류에서 복구 → 답 확정 → 공유 보기 해설 → 다음 → 의도적 오답 → 최종 결과 → 오답 복습 설정/시작 완료
- 문항·결과 제목 초점이 예측 가능하며 보기 선택만으로 자동 이동하지 않음. 헤더 초점의 시각적 표시 확인
- 실제 두 번째 앱 탭에서 편집 잠금 안내 확인. 원래 탭 새로고침·빠른 반복 이어풀기 후 DNS 선택과 보기 순서 유지
- 시간제 실기1분: 정확한60초 경과 기록, 부분점수1·미응답1·3/20점 확인. 진행 중 AI 버튼 비활성, 피드백·프롬프트 DOM 없음
- 코드와 의도적 HTML/스크립트 문자열이 텍스트로 유지되고 실제 이벤트 핸들러로 만들어지지 않음
- 실기 코드 파일/줄 탐색과 별도 줄 번호 표시 확인. hidden CSS 결함 수정 후 비표시 상태를 재검증
- 새로 생성한0.1.1 비교 프롬프트에 서술 지시,10점 서술 루브릭,별도 고정 답안 키,비합산 지시,저장된 사용자 텍스트가 모두 나타남
- 복사 버튼에서 브라우저 복사 API 성공 안내 확인. 수동 전체 선택의 전체 문자 범위 확인. 클립보드 권한 거절 분기를 강제로 재현한 것은 아님
- 320 CSS px 프레임에서 홈·실기 재배치와 가로 넘침을 점검함. 실제 모바일 기기나 브라우저200%/400% 확대 검사가 아님

## 통과: 실제 IndexedDB 격리 harness

2026-10-01 15:45:29 UTC,0.1.1에서 `qa/harness.html`의 9항목 모두 PASS. 일반 학습 기록과 별도인 QA 데이터베이스를 사용했습니다.

1. 동시 revision 비교 쓰기에서 한 건 성공·다른 건 충돌
2. Web Locks의 두 번째 편집자 거절·해제 후 재획득
3. 만료/제출 경합에서 한 번의 최종 저장
4. JSON 왕복·가져오기·중복/충돌 ID의 기존 기록 보존
5. 손상/변조/버전/크기 오류의 무변경 거절
6. 전환 old/new의 원자 저장과 목적지 중복 시 rollback
7. 정상 은행 적용 및 모형 hash/schema/network 오류에서 마지막 정상본 보존
8. 트랜잭션 중단 시 기존 세션 보존·오류 전달
9. IndexedDB 사용 불가 오류 전달

이 harness는 실제 브라우저 DB를 쓰지만 일부 실패 원인은 제어된 모형으로 만듭니다. 실제 기기 디스크를 가득 채우거나 운영 서버에 손상 파일을 공개했다는 뜻은 아닙니다.

## 미검증·미실시

- **Windows + NVDA 수동 검사: 미실시**. [NVDA 수동 점검 목록](NVDA-CHECKLIST.md)을 실제 환경에서 완료해야 함
- 실제 브라우저200%/400% 확대·실제 모바일 기기: 미실시
- 클립보드 권한 거절 후 fallback: 권한 거절을 강제로 재현하지 않음. 수동 전체 선택 경로는 점검
- **파일 다운로드 완료: 미검증**. 버튼 실행 후 앱의 다운로드 요청 안내는 보았지만 도구의 다운로드 이벤트/파일 경로 확인이 시간 초과됨. 도구만의 문제 또는 앱 실패 중 어느 쪽이라고 단정하지 않음. 브라우저 Downloads 페이지 직접 읽기도 정책상 불가하여 우회하지 않음
- 메인 파일 선택기에서 실제 다운로드 파일을 고른 UI 가져오기: 미실시. JSON 파서·실제 IndexedDB 가져오기/합치기/중복/rollback 검사는 별도로 통과
- 실제 저장 용량 소진·기기 절전·지원 대상 전체 브라우저 조합: 미실시. 제어된 실패/시계와 새로고침/만료 경계만 검증
- 최종10월17일 동결과 정기 운영 실행은 앱 검사와 별개로 실제 실행·공개 확인 필요

## 발견한 문제와 수정

- 선택 해제한 줄 번호 textarea가 author display:block 때문에 노출됨: 전역 `[hidden]{display:none!important}`와 회귀 검사 추가, 실제 비표시 재확인
- 서술 루브릭과 고정답안 배점을 합산할 수 있는 프롬프트 모호함: 구역을 분리하고 비합산·서술 미작성 처리를 명시, 실기 서술 지시 포함
- 정상 새로고침 뒤 새 프롬프트 코드가 즉시 보이지 않음: 앱/모듈/CSS/QA 자원에 일관된 버전 URL을 도입하고 바닥글0.1.1 및 실제 새 프롬프트 출력을 확인. 캐시가 유일한 원인이라고 단정하지 않음
- 다운로드 URL을 고정1초 후 폐기하던 잠재적 경합:0.1.2에서 문서 수명 동안 유지하도록 보완. 브라우저가 문서 종료 시 정리하며 앱은 완료를 주장하지 않음. 이 변경만으로 실제 파일 수신을 검증했다고 보지 않음

## 재현 및 수용 기준

`npm ci && npm run verify`로 자동 검사를 실행합니다. `qa/harness.html`은 격리 저장소 검사, `qa/viewport.html`은 명시적 버튼으로 여는320px 프레임 검사입니다.

AC01~04: 출제/공유보기 자동 검사와 실제 필기 흐름. AC05~08: 시간/경합/분모/과락 자동 및 실제1분 만료. AC09~10: 실기/텍스트 안전성/프롬프트 실제 생성 확인, 파일 수신은 미검증. AC11: 통계 분리/도움 노출/정정 회귀. AC12~13: 업데이트·복원·실제DB harness, 메인 파일 선택기 왕복은 미실시. AC14: 핵심 키보드 흐름 통과. AC15: NVDA NOT RUN. AC16: 텍스트 렌더링·위험 URL 및 실제 DOM 점검. AC17: 모형 실패/실제DB rollback 통과, 실제 저장 용량 소진 미실시. AC18: guard/경계 자동 검사, 미래 최종 운영 동결은 별도.
