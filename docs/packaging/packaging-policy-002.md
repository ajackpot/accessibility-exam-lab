# packaging-policy-002: 전체 7z와 변경분 ZIP

효력: 2026-10-08 사용자 명시 승인 이후 새 전달 준비부터 적용한다. 이전 packaging-policy-001의 자체 완결 전체본 요구를 유지하고 새 기본 전체본 형식만 ZIP에서 7z로 전환한다. 변경분은 ZIP을 유지한다.

최초 적용의 내용 기준은 이미 전달된 round-032의 **일반 915개 + 시드 14개**다. 원 032 전체 ZIP·변경분 ZIP과 전달 증거는 불변 이력으로 보존하고, 새 전체 7z에는 검토된 포장 지원 코드·문서·외피 변경만 반영한다. 신규 학습 문항과 개정 문항은 모두 0개다. 2026-10-08 이 개정 준비 시 실제 공개 확인 기준은 round-031의 일반 908개 + 시드 14개이며, 포장 전환으로 round-032가 Git/Pages에 공개되었다고 기록하지 않는다. 이미 전달한 동일 delta는 중복 첨부하지 않는 기존 추가 전체본 전달 규칙을 따른다.

- 전체본은 일반 7z 해제 한 번으로 `project/`·`manifest.json`·`APPLY-KO.txt`를 제공한다. 이전 archive·순차 delta·별도 복원 스크립트가 필요하지 않다
- 전체 공개 허용 목록과 필요한 불변 은행·종결 대장·과거 전달/공개 증거를 모두 보존한다. `.git`, 비공개 검토 자료, 서비스 식별자, 비밀과 개인 학습 기록은 포함하지 않는다
- 새 complete manifest는 v2/`archiveFormat:7z`이며 과거 v1/ZIP과 delta 계약은 그대로 검증한다. 형식 판정과 선언이 다르거나 실제 바이트·경로·CRC·크기·SHA-256 검사가 실패하면 차단한다
- 정확한 base의 delta 재구성과 일반 도구의 빈 폴더 전체본 해제를 각각 검증한다. 전체 검사 또는 validation-efficiency-001의 엄격한 증거 재사용 조건을 충족해야 한다
- artifact별 실제 형식·바이트 수·SHA-256, Library 저장과 native 첨부 수락을 확인한 뒤 전달 상태를 기록한다. 현재 20 MiB 운영 점검선은 관측에 근거하며 보편적 공식 제한이 아니다
- 원 ZIP·proof·trust·은행·closed 대장·runtime·학습 기록을 바꾸지 않는다. 새로운 문항/개정판·권한·Git 쓰기·비용·자격증명·전달 목적지를 추가하지 않는다. 기존 일정·유한 검토·동결·최종 cutoff는 그대로다

이 문서는 정책과 수용 조건이며 구현·검증·첨부 성공의 영수증이 아니다. 자세한 요구사항은 [PRD](../PRD.md), 절차는 [OPERATIONS](../OPERATIONS.md), 형식과 검증 경계는 [DATA-CONTRACT](../DATA-CONTRACT.md)를 따른다. 과거 실패·미실시·공개 상태를 새 성공으로 바꾸지 않는다.

이번 최초 전환본은 검토된 전체 소스를 기준으로 새 변경분 ZIP과 전체 7z를 함께 준비한다. 새 변경분은 공개 기준 d6179e877c033dda52c87bfb5c2be8e5d42bb0cb에서 포장 지원 코드·문서와 별도로 검토한 032 전달 기준 등록까지 실제 변경된 파일을 담는다. 원래 032 ZIP 쌍과 그 proof는 계속 불변 이력이며, 새 쌍의 artifact 해시·전달 영수증은 별도로 기록한다. 은행·closed 대장·신규 학습 수는 바뀌지 않는다.

후속 회차의 offlinePredecessor는 등록된 원 032 전달 root의 artifact·manifest·ledger 해시를 사용한다. 이번 포장 개정본의 새 파일 해시로 원 root를 교체하거나 같은 은행에 두 번째 root를 만들지 않는다.
