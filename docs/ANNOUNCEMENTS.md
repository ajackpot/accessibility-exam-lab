# 알림·초점 정책 (0.2.5)

이 문서는 앱의 이벤트·DOM 계약입니다. Windows/NVDA 실제 음성 검증은 아직 수행하지 않았습니다. 브라우저/화면 낭독기 조합에 따라 실제 발화가 달라질 수 있으므로 [수동 점검](NVDA-CHECKLIST.md)이 필요합니다.

## 안내를 만드는 시점

1. **정상 자동 저장:** 답 선택/입력, 서술, 표시, 위치, 자료/해설 열람의 성공 저장은 자동 알림을 만들지 않습니다. 모든 풀이 화면에 자동 저장을 설명하는 일반 문장이 있습니다
2. **현재 문항의 명시적 개별 채점:** 사용자가 누른 채점이 실제 저장된 뒤, 현재 화면/세션/문항이 그대로일 때 한 번의 polite 상태 변경을 만듭니다. ‘N번 문항. 정답입니다.’ 또는 ‘오답입니다.’, 부분 정답은 실제 점수/배점을 덧붙입니다. 같은 판정이어도 다른 문항 번호는 독립 이벤트입니다
3. **입력 없는 개별 채점:** 기존 도메인 규칙에 따라 입력 안내 오류입니다. 빈 답·자유 서술만 있는 답을 자동으로 확정하거나 새 시도로 만들지 않습니다. 실제 종료 결과에 속한 미응답의 표시 문장은 ‘답을 제출하지 않았습니다.’를 유지합니다
4. **공개 제한:** 종료 후 해설 설정에서는 개별 채점 완료만 알립니다. 시간제 진행 중 개별 채점·정오 공개는 없습니다. 종료 시 문항별 판정을 live region에 순서대로 밀어 넣지 않습니다
5. **이미 있는 결과:** 렌더링·이전/다음·기록·새로고침·이어 풀기에서는 자동 판정을 만들지 않습니다. 해설은 일반 문서 구조로 계속 읽을 수 있습니다
6. **실패와 복구:** 저장 실패는 성공 알림 없이 입력을 보호하고 긴급 백업·재시도를 제공합니다. 하나의 실패를 처리한 뒤 상위 이벤트가 같은 오류를 다시 렌더링하지 않습니다. 시간 만료와 저장 실패가 겹친 경고는 매초 반복하지 않습니다. 명시적 재시도가 실패했던 개별 채점을 처음 저장한 경우에만 복구와 허용된 판정을 함께 알립니다. 이미 저장된 채점은 복구에서 재생하지 않습니다
7. **요청한 작업:** 복사/다운로드 요청, 저장 후 나가기, 시간 연장/전환, 설정 저장, 수동 은행 확인, 가져오기/삭제의 필요한 완료·실패 안내는 유지합니다. 시작 시의 문제 제목/화면 전환으로 알 수 있는 준비 완료와 백그라운드 은행 확인의 성공은 추가 알림을 만들지 않습니다

## 단일 판정 경로와 초점

- 문서에 처음부터 존재하는 `#status`는 `role="status"`, `aria-live="polite"`, `aria-atomic="true"`입니다. 영역을 새로 붙이거나 초점을 주지 않고, 비운 뒤 다음 animation frame에서 허용된 현재 이벤트만 넣습니다
- 채점 자체는 전체 본문을 다시 만들지 않습니다. 원래 버튼은 연결/초점 가능 상태를 유지하고 ‘채점 완료’로 바뀝니다. `aria-disabled="true"`와 실행 가드로 재채점을 막습니다. 답 입력은 채점 진행 중 잠그고, 단순 입력 오류면 다시 열며 저장 실패면 복구 전까지 보호합니다
- 판정/해설 heading은 static입니다. 제목·heading·입력의 설명 속성에 판정을 복제하지 않습니다. 사용자가 직접 해설을 탐색하는 것과 자동 판정 이벤트는 구분합니다
- 새 화면으로 가면 보류/기존 현재 문항 알림을 취소합니다. 오래된 microtask가 새 화면 제목에 다시 초점을 주지 않습니다. 실제 다른 화면 이동은 기존처럼 해당 제목으로 이동합니다
- 복구 중 제거된 alert의 재시도 버튼에 초점이 있었다면, 처음 저장된 현재 채점의 연결된 ‘채점 완료’ 버튼으로 옮깁니다. 사용자가 다른 곳에 옮긴 초점은 억지로 가져오지 않습니다

| 공통 `#alert` | 작업 오류·저장 실패/충돌. 같은 오류의 중복 호출 차단 |

## 근거와 검증 한계

[WAI 상태 메시지 이해 문서](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)는 작업 결과를 초점 변경 없이 보조기기에 전달하는 상태 메시지를 설명하며, 중요하지 않은 과도한 알림을 경계합니다. [MDN status 역할](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/status_role)은 polite/atomic 기본값과 status 자체로 초점을 옮기지 않는 사용을 설명합니다. [MDN live region 안내](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Guides/Live_regions)는 변경 전에 영역을 준비하고 polite로 필요한 내용을 전달하는 방식을 다룹니다. 문서 확인일: 2026-10-02.

자동 테스트는 저장 성공/실패, DOM 상태 변경 횟수, 연결된 초점 대상, 연속·중복 동작, 새 화면 경합, 공개 정책을 검증합니다. fake DOM은 실제 accessibility tree/발화를 구현하지 않습니다. 상세 수행 결과는 [검증 기록](VALIDATION.md)을 봅니다.
