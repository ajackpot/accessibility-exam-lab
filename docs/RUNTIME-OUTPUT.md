# 선택형 로컬 런타임 출력

`npm run build`의 전체 소스 검증과 기존 COMPLETE/DELTA 계약은 그대로 유지합니다. 다음 명령은 전체 소스에서 같은 활성 은행·신뢰·이력·해설 검사를 수행한 뒤, 브라우저 실행에 필요한 원문 파일만 새 폴더로 복사합니다. 기본 빌드의 후보 은행 위치 인자와 혼동하지 않도록 별도 명령을 사용합니다.

```sh
npm run build:runtime -- ../runtime-preview
python3 -m http.server 4173 --directory ../runtime-preview
```

출력의 부모 폴더는 이미 존재해야 하고 출력 폴더는 없어야 합니다. 소스와 겹치는 경로, 심볼릭 링크, 기존 출력의 덮어쓰기는 거부합니다. 실패한 부분 출력은 보존하며 자동 삭제·덮어쓰기·재시도하지 않습니다. 새 출력은 정본 소스나 사용자 데이터를 변경하지 않습니다.

현재 출력은 `index.html`, `style.css`, `src/`의 실제 런타임 9모듈, `data/manifest.json`, 그 manifest가 가리키는 활성 `bank.json`, 앱에서 링크하는 `docs/NVDA-CHECKLIST.md`의 14파일입니다. manifest와 은행, 버전/query가 붙은 모듈 주소를 재작성하거나 minify하지 않습니다. 새 실행 자산이 생기면 선택 목록과 해당 자산 검사도 함께 갱신해야 합니다.

이 폴더는 로컬 브라우저 미리보기이며 완전한 프로젝트·COMPLETE·DELTA·학습 기록 백업이 아닙니다. 빌드/검증 스크립트, 개발 설정과 역사 은행은 보존된 전체 프로젝트에 있습니다. 출력 안에서 `npm run build`, 전체 이력 검증이나 COMPLETE 생성을 실행하는 용도가 아닙니다. 기존 공개 사이트를 이 폴더로 교체하는 배포는 이 명령의 승인 범위가 아닙니다.

저장된 세션은 내장 문항·선택지·답안·점수 스냅샷으로 재개합니다. 런타임 모듈, IndexedDB 이름·버전, CAS/잠금, 백업 스키마와 채점 규칙은 변경하지 않습니다. 브라우저 저장소를 지우지 마세요. 프로토콜·호스트·포트가 달라지면 별도 저장소이며, 기존 기록이 자동 이동하지 않습니다. 개인 기록 호환성 점검은 백업을 보존하고 별도 브라우저 프로필에서 수행하세요.

과거 은행 URL과 구버전 manifest가 요구하는 파일은 이 경량 폴더에 없을 수 있습니다. 옛 manifest를 가진 클라이언트, 과거 URL 직접 조회, 구버전 은행·설정·이력·seed·출제기로 다시 생성하는 작업의 호환성을 보장하지 않습니다. 저장 스냅샷 재생과 구버전 입력 재생성은 구별합니다. 공개 배포 전에는 기존 URL 보존/제공 전략, 캐시·열린 구버전 클라이언트, 같은 origin과 실제 배포 경계를 별도로 검토해야 합니다.

크기 비교는 기본 빌드가 끝난 전체 프로젝트와 별도 런타임 출력의 파일 수·원시 바이트·파일시스템 할당량을 구분합니다. 기본 빌드는 별도 dist를 생성하지 않으므로 전체 작업 사본을 준비하는 복사 시간과 기본 빌드 시간을 따로 기록합니다. 경량 출력 시간에는 같은 활성 은행 검증과 필요한 파일 복사를 포함합니다. 원본 전체 트리의 크기나 브라우저 메모리가 줄었다고 해석하지 않습니다. 이 기능의 로컬 검증을 전체 테스트·공개 배포·Windows/NVDA 통과로 표시하지 않습니다.
