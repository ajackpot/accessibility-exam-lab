## 바꾸는 기준

오답에 `만`, `항상`, `절대` 같은 표현이 몰리는 패턴, 정답만 긍정적이고 오답은 노골적으로 나쁜 행동을 제안하는 패턴, 관련 없는 기술 효과, 문법·길이·세부 정보·반복 어휘로 드러나는 정답을 검토한다. 오답은 실제로 혼동할 수 있는 범위·기능·대상·원리의 차이로 구성하고, 정답 집합은 그대로 유지한다.

단어 자체를 금지하지 않는다. CSS 선택자의 정확한 매치 집합을 뜻하는 `workshop만`·`morning만`·`afternoon만`, 대비의 **최소** 조건, 실제 코드 연산자·속성·ARIA 상태값, HTML의 같은 form/트리 조건, HTTP404의 존재 비공개 의미는 지식과 단일 정답성에 필요해 보존했다. 기초 정의·계산 문항을 쉽다는 이유만으로 바꾸지 않는다.

## 검토 방식과 조건 보존

정답·해설·출처 메타데이터·의미를 암시하는 내부 ID를 제외하고 선택지 순서를 섞은 중립 자료를 먼저 제공했다. 필기 15개는 08:13:08 UTC, 실기 7개의 22개 세부 항목은 08:20:14 UTC에 독립 답을 확정했다. 두 묶음 모두 확정한 뒤에만 정답·원문·근거를 공개했다.

이후 1차 출처·지정 판·범위·권리, 단일 정답과 반례, 문안·접근성, 자동 구조 검사를 같은 개정판에 수행한다. 조건과 학습 목표가 달라지면, 독립 답이 키와 일치해도 채택하지 않는다.

`r001-standards-s5-w06`의 1차 개정안은 음성 통화만 제공한다는 사실을 빠뜨리고 발화의 어려움을 발화 불가능으로 좁혔으므로 **수정 판정**했다. 원래 시나리오를 복원한 후 새로운 독립 풀이자가 08:34:19 UTC에 답을 확정하고, 08:39:30 UTC에 다섯 검사를 모두 통과했다. 최종 문항은 개정 3이며 실패한 초안 개정 2를 건너뛰는 이유를 대장에 남겼다. 처음 실패한 문항 개정판과 검토 횟수는 숨기거나 초기화하지 않는다.

## 이력·발행 계약

- 동일 questionId·optionId·templateId·learningGoalRevision과 정답·배점·실기 항목 순서를 유지한다. 바뀐 문항·선택지에 새 개정판을 부여한다
- 현재 검토의 정확한 이전 채택 문항 개정판·내용 해시를 연결한다. 한 선행본에서 시작한 검토는 최대 3회이며 다른 ID·대장으로 실패를 초기화하거나 후속본을 분기하지 않는다
- 이후 정말 다른 결함이 생기면, 실제 공개 확인까지 끝난 후속 채택본을 새로운 선행본으로 삼을 수 있다. 미공개 초안은 선행본이 될 수 없다
- 새 누적 은행은 최신 공개 확인본을 기준으로 만든다. 이후 일반 확대 회차도 정정이 반영된 최신 은행을 이어받아야 하며 이전 기준본으로 되돌아가 다른 문항의 정정을 없애면 안 된다
- 새 문항·새 지식 추가, 탈락 후보의 근거 있는 재개방, 기존 답안의 invalid/key 점수 정정과 이번 편집 경로를 구분한다
- `round-001`의 종결 결정과 기존 불변 은행·시드·저장 세션·답·점수·선택지 순서·스냅샷 해시는 변경하지 않는다
- 필기 15개의 추가 정보 없는 문맥 해설 75개는 생략하고, 선택지 이유는 기본 해설 한 곳에 둔다. 새로 바뀐 필기 문항 전체에 엄격한 해설 저작 검사를 적용한다

## 시드에 남는 한계

시드는 역사적 기능 검증 자료로 보존한다. `seed-w10`과 `seed-p01`~`seed-p04`에는 과도한 단정, 관련 없는 기술 효과, 정답만 완전한 조치 등을 제시한 과거 문안이 남는다. 해당 조건의 정규 문항이 있으면 일반 연습은 정규 문항만 사용한다. 시드·기존 기록·명시적 복습을 몰래 다시 쓰지 않는다.
